## 3. Phase Analysis

### Phase 4: Config Schema & Personality Injection
- **Goal:** Mở rộng cấu hình JSON và TypeScript types với các trường autoChat mới, và tích hợp cơ chế nạp cá tính (personality prompt) động từ file txt vào GeminiService.
- **Status:** passed (verified via `04-VALIDATION.md` and summaries)
- **Key Achievements:**
  - Extended the `Configuration` interface with optional `autoChatCharacter`, `autoChatCharacterName`, `autoChatBotIDs`, and `autoChatChannelID` fields.
  - Standardized the conditional configuration prompting in `src/structures/Inquirer.ts` with strict alphanumeric validation to block path traversal, and snowflake validation for Discord IDs.
  - Implemented dynamic system instructions in `src/structures/GeminiService.ts` via `setSystemInstruction()` and parameterized response cleaning (dynamically removing prefix characters based on the bot's configured name).
  - Wired startup personality loading in `src/structures/BaseAgent.ts` with secure path traversal regex checks (`/^[a-zA-Z0-9._-]+$/`), falling back gracefully (turning autoChat off without crashing) if a file is missing.

### Phase 5: Mention/Reply Triggers & Human-like Response
- **Goal:** Tái cấu trúc AutoChatManager để chỉ phản hồi các lượt mention/reply từ các bot trong nhóm, giả lập hành vi gõ chữ và độ trễ ngẫu nhiên, và định tuyến phản hồi tự động dựa trên quyết định tag của Gemini.
- **Status:** passed (verified via `05-VALIDATION.md` and summaries)
- **Key Achievements:**
  - Replaced legacy handlers with a FIFO message queue capped at `MAX_QUEUE = 3` and a `10_000ms` deduplication window per sender to maintain a clean interaction loop.
  - Enforced strict sender validation utilizing an ID `Set` from `autoChatBotIDs` to ignore unknown users silently.
  - Implemented natural typing simulation (`simulateBurstTyping`) with typing indicators updated every 1-3 seconds over a randomized 5-15s interval, executing in parallel with the Gemini API call via `Promise.all` to optimize responsiveness.
  - Developed in-character mention extraction using regex `/<@!?(\d+)>/g` and target ID validation, routing replies directly using message replies (0 mentions) or standalone messages with allowed mentions (1+ mentions).
  - Integrated split routing for long responses (>100 characters) into natural sub-sentences sent with 2-5s conversational intervals.

### Phase 6: Conversation History & Initiator
- **Goal:** Quản lý lịch sử hội thoại dùng chung theo từng channel qua Redis (RAM fallback), và thiết lập cơ chếrotating initiator tự động bắt đầu chủ đề nói chuyện.
- **Status:** passed (verified via `06-VALIDATION.md` and summaries)
- **Key Achievements:**
  - Designed the `ChannelHistoryManager` class with dual-layer caching (RAM `Map` + Redis key `autochat:history:{channelId}`) capped at `20` messages with a `30-minute` expiration.
  - Standardized prompt history formatting to feed the last 20 messages into the Gemini API under the `Sender: Content` sequence.
  - Registered an atomic custom `claimInitiator` Lua script to claim the initiator role, validating a `15-minute` quiet channel threshold and round-robin turn index atomically on Redis.
  - Wired periodic initiator checking intervals (randomized every 5-10 minutes) with automatic sequence failovers.
  - Enabled configurable Gemini models, dynamically setting `gemini-2.5-flash-lite` by default instead of a hardcoded string.
  - Ensured consistent conversation history write times (writing messages to history *before* sending them to Discord).

## 4. Cross-Phase Integration & E2E Flow Check

A rigorous review of E2E user flows and cross-phase wiring yields the following verified integration paths:

### 1. Interactive Configuration Flow
- **Flow:** `Inquirer` checks `autoChat` enabled -> conditionally prompts for personality filename, character display name, bot IDs array, and target channel ID -> writes to JSON -> TypeScript validates contracts.
- **Wiring:** Compiles cleanly with zero structural configuration errors.

### 2. Startup & Personality Initialization Flow
- **Flow:** `BaseAgent` on startup -> checks `autoChat` config -> validates personality file against path traversal regex -> reads UTF-8 plain text from `src/config/personalities/` -> resolves the participant bot usernames via Discord's `users.fetch()` -> compiles and sets system instruction on `GeminiService`.
- **Wiring:** Perfect. Bot names are dynamically injected into the system instruction, and a missing personality file triggers an error log while disabling the feature gracefully.

### 3. Message Trigger & Queue Worker Flow
- **Flow:** Discord message received in channel -> `AutoChatManager.isTrigger()` checks channel ID, author ID check against `autoChatBotIDs` Set, and presence of direct mention or reply -> `enqueueTrigger()` adds message to queue, applying 10s sender deduplication -> queue worker pops and processes.
- **Wiring:** Flawless. Silently ignores all non-bot participants and unknown users, eliminating noise and preventing infinite reaction loops.

### 4. Parallel Processing & Human Simulation Flow
- **Flow:** Queue worker pops message -> reads shared conversation history -> spawns `geminiPromise` and `typingPromise` (calling `channel.sendTyping()` in a loop with random intervals) in parallel via `Promise.all` -> waits for both to complete.
- **Wiring:** Smooth. Displaying typing status during API request generation mimics actual human latency.

### 5. Mention Extraction & Response Routing Flow
- **Flow:** Gemini returns response text -> `parseAndValidateMentions` extracts Discord mention structures -> validates mentioned accounts against the known bot IDs list (stripping invalid ones) -> routes to `trigger.reply()` (0 mentions) or `channel.send()` (1+ mentions) -> splits long chunks (>100 chars) with random typing delays.
- **Wiring:** Dynamic and reliable. Ensures the conversational replies look completely natural and keeps all tagging restricted strictly to the group.

### 6. Initiator Loop & Turn Claims Flow
- **Flow:** `startInitiatorCheck()` runs check interval -> calls `checkAndInitiate()` -> evaluates atomic Lua script `claimInitiator` on Redis -> if channel has been quiet for 15+ minutes and it is this bot's round-robin index turn -> claims successfully -> generates starter topic via Gemini -> writes to history -> broadcasts mentions with burst typing.
- **Wiring:** Thread-safe and atomic. Avoids multi-process race conditions where multiple bots claim the initiator role simultaneously.
