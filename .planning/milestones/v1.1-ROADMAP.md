# Milestone v1.1: Advanced AutoChat & Multi-bot Roleplay

**Status:** ✅ SHIPPED 2026-05-19  
**Phases:** 4-6  
**Total Plans:** 6  

## Overview

Rewrite the core `autoChat` feature so 5 selfbot processes (1 per Discord account) roleplay as distinct characters and converse naturally in a shared channel — triggered only by mentions/replies, with human-like delays, shared caching history via Redis, and round-robin initiator rotation.

## Phases

### Phase 4: Config Schema & Personality Injection

**Goal**: Extend config schema and TypeScript contracts, load personality txt file, and inject into GeminiService system instructions.  
**Depends on**: Phase 3  
**Plans**: 3 plans  

Plans:
- [x] 04-01-PLAN.md — Extend Configuration interface + create personalities directory
- [x] 04-02-PLAN.md — Dynamic systemInstruction in GeminiService + personality loading in BaseAgent
- [x] 04-03-PLAN.md — Inquirer prompts for new autoChat config fields

**Details:**
- Update `Configuration` and JSON files with fields `autoChatCharacter`, `autoChatCharacterName`, `autoChatBotIDs`, `autoChatChannelID`.
- Handle startup loading inside `BaseAgent.ts` with strict regex `autoChatCharacter.match(/^[a-zA-Z0-9._-]+$/)` to block path traversal attempts.
- Dynamically remove personality prefixes inside `GeminiService.ts` using custom regex from `autoChatCharacterName`.

---

### Phase 5: Mention/Reply Triggers & Human-like Response

**Goal**: Only respond to valid bot ID mentions/replies in target channel, queue triggers (max 3), simulate typing in parallel, and route based on in-character mention decisions.  
**Depends on**: Phase 4  
**Plans**: 1 plan  

Plans:
- [x] 05-01-PLAN.md — Rewrite AutoChatManager with queue, burst typing, mention extraction, and response routing

**Details:**
- Queue triggers in a FIFO array (max 3) to prevent reaction loops, applying a 10s sender deduplication window.
- Silently drop triggers from unknown users.
- Spawns Gemini generation and realistic Discord typing (`channel.sendTyping()`) in parallel via `Promise.all`.
- Validates in-character mention extraction using `/<@!?(\d+)>/g` against the bots set.
- 0 mentions: direct reply. 1+ mentions: new message with target tags. Split responses > 100 chars with conversational random intervals.

---

### Phase 6: Conversation History & Initiator

**Goal**: Synchronize conversation history in shared Redis cache (RAM fallback), inject history into prompts, and claim rotating initiator slot atomically.  
**Depends on**: Phase 5  
**Plans**: 2 plans  

Plans:
- [x] 06-01-PLAN.md — ChannelHistoryManager with Redis/RAM cache, history injection into Gemini prompt, history write after send
- [x] 06-02-PLAN.md — Rotating initiator with Lua script, periodic check timer, Gemini-generated opening topic with burst typing

**Details:**
- Create `ChannelHistoryManager` utilizing RAM `Map` or Redis hash `autochat:history:{channelId}` (expires in 30 minutes, max 20 items).
- Appends context to the Gemini prompt in `Sender: Content` sequences.
- Writes history *before* sending to Discord to ensure strict chronological coherence.
- Claims rotating initiator slot atomically via Redis Lua script checking a 15-minute channel quiet threshold and round-robin index turns.

## Milestone Summary

**Decimal Phases:**
- None.

**Key Decisions:**
- **Decision: 5 separate processes (1 per bot)** (Rationale: Discord events serve as natural IPC, crash isolation, simple BaseAgent design).
- **Decision: FIFO interaction queue (max 3) and 10s dedup window** (Rationale: Prevent message floods and self-interaction loops).
- **Decision: Parallel typing & API execution** (Rationale: Hide Gemini API latency and mimic human typing).
- **Decision: Dual-storage Redis/RAM channel history cache** (Rationale: Shared state access with zero thread blocks).
- **Decision: Atomic Lua claimInitiator script** (Rationale: Eliminate multi-process race conditions).
- **Decision: Write history before sending** (Rationale: Absolute chronological order preservation).

**Issues Resolved:**
- TypeScript type parameters made strictly optional for seamless integration.
- Path traversal surface fully secured at startup validation.

**Issues Deferred:**
- None.

**Technical Debt Incurred:**
