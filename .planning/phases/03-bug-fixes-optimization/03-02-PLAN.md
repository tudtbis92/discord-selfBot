<task id="03-02-T3" type="execute">
<title>Add rate-limit detection and retry wrapper</title>
<read_first>
- src/structures/GeminiService.ts (parseGeminiError function, lines 20-96)
</read_first>
<action>
Add two utility functions to `GeminiService.ts`:

1. `isRateLimitError(error: unknown): boolean` — returns true if error matches 429, RESOURCE_EXHAUSTED, RATE_LIMIT_EXCEEDED, or quota patterns. Reuse the same string checks from `parseGeminiError`.

2. `sleep(ms: number): Promise<void>` — simple `new Promise(resolve => setTimeout(resolve, ms))`.

3. `withRetryAndRotation<T>(fn: (ai: GoogleGenAI) => Promise<T>, keyManager: ApiKeyManager, createAi: (key: string) => GoogleGenAI): Promise<T>` — retry wrapper that:
   - On rate-limit error: calls `keyManager.markFailed(currentKey)`, tries `keyManager.rotateToNext()`
   - If next key available: creates new GoogleGenAI instance, retries immediately
   - If all keys exhausted: applies exponential backoff delays `[5000, 15000, 45000, 135000, 300000]` ms, resets failed keys, retries
   - Max 5 total backoff cycles before throwing
   - Logs rotation: `logger.warn('[GeminiService] API Key #N failed (rate limit). Rotating to API Key #N+1...')`
   - Logs backoff: `logger.warn('[GeminiService] All API keys rate-limited. Waiting Ns...')`
   - Non-rate-limit errors propagate immediately without retry
</action>
<acceptance_criteria>
- `isRateLimitError` correctly identifies 429, RESOURCE_EXHAUSTED, RATE_LIMIT_EXCEEDED
- `withRetryAndRotation` retries with key rotation before backoff
- Non-rate-limit errors (401, 403, 404, network) are NOT retried
- Backoff delays follow pattern: 5s, 15s, 45s, 2m15s, 5m
</acceptance_criteria>
</task>
